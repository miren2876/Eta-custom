# 衰减规则与驱逐优先级

## 日期标注约定

工作记忆条目（`memory/MEMORY.md`）、用户画像（`USER.md`）与主题档案（`memory/files/*.md`）中的内容都可带日期前缀 `[YYYY-MM-DD]`（创建日期，永不更新）。GC 用它计算年龄；无日期内容只按"是否仍成立"判断。

## 条目重要度（1–5）

| 重要度 | 适用 | 注入表现 |
|--------|------|----------|
| 5 | 关键决策、硬约束、必须记住的结论 | 基础权重 1.0，长期排在前面 |
| 4 | 重要事实、进行中的项目主线 | 0.8 |
| 3 | 一般事实（缺省） | 0.5 |
| 2 | 低优先级补充 | 0.3 |
| 1 | 临时信息，最先被挤出注入 | 0.15 |

EI = 基础权重 × 访问因子 max(1, ln(1+引用次数)) × 30 天半衰期衰减。常被检索的条目自然上浮；60 天没被碰过的条目 EI 会掉到初始值的 1/4 以下。

## 复查阈值

| 类别 | 典型内容 | 动作 |
|------|----------|------|
| 硬约束 / 用户规则 | "发送前必须确认" | 永不衰减（重要度 5） |
| 关系 | 人名、与用户的关系 | 永不衰减；90 天未提及才复查 |
| 稳定偏好 | 语气、工具、格式偏好 | 60 天复查：仍成立？ |
| 持久事实 | 工作环境、长期习惯 | 60 天复查：仍成立？ |
| 进行中项目 | 活跃工作流 | 21 天复查：仍在进行？ |
| 环境状态 | ROM、已装工具、设备配置 | 30 天复查 |
| 任务记录 | 一次性待办 | 14 天复查；已完成即删条目 |

"复查" = 判断题，倾向保留。每次删除都要写进 GC 汇报。

## 驱逐优先级（超出容量目标时）

目标：用户画像 ≤ 5 KB、工作记忆 ≤ 10 KB（单条 ≤ 500 字符）。按顺序驱逐：

1. 已完成的条目（重要度 1–2）
2. 30 天以上的环境状态条目（可从 device_status / inspect_app 重新推导）
3. 14 天以上的任务记录
4. 21 天以上且近期未提及的项目条目
5. 同一层级内先驱逐最长的条目（细节应先挪进档案再删）

主题整体不再需要常驻时，把档案归入 `memory/archive/`（一档一文件，记忆页可归档、可还原），而不是直接删文件。

## 受保护内容

永不驱逐、永不改写：

- 用户明确要求记住的内容
- 硬性行为约束
- 关系类条目（人名）

受保护内容过期时，向用户标记而非删除。

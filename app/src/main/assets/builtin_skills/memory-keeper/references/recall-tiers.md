# 分级召回细节

## 各层级说明

- **L0** — 每轮注入的 `USER.md`（用户画像）与 `MEMORY.md` 里按 EI 排序的活跃条目。零成本，答案在此即结束。
- **L1** — `memory_get query=<关键词>` 同时检索工作记忆条目与主题档案（命中累加各自的引用次数，进而抬高 EI）；已知档案名时用 `memory_get archive=<名字>` 读全文。细节大多在这一层。
- **L2** — `conversation_history query=...` 搜索历史会话。适合"我们决定过什么"、"上次聊到 X 是什么时候"。
- **L3** — 设备领域工具，按主题选择：search_calendar_events（日程）、search_notes / search_todos（便签与待办）、search_system_memories（系统提取的事件）、search_bills（消费）、search_messages / search_call_history（通讯）、search_flights / search_trains / search_hotels（出行）。

## 不确定性闸门

1. 从 L0 开始，给当前答案的置信度打 0–1 分。
2. 置信度 ≥ 0.7 → 回答。
3. 否则扩展一层，重新作答、重新打分。
4. 若新层带来的置信度提升 < 0.1 → 停止扩展，更多上下文只是噪声。说明已找到什么、还有什么不确定。
5. 硬上限 L3。仍 < 0.7 就直说不知道。

查询形状明确时可以跳层：日期型问题直接查日历；精确引述型问题直接查会话历史；明确属于某个主题的问题直接读对应档案。

## 输出形状

- 单一明确答案 → 陈述事实并附证据：来源层级 + 日期。
- 多个匹配 → 简要列出并附日期，让用户挑。
- 无匹配 → 直说没有找到，不编造。
